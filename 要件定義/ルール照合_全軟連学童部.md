## 1. 投球数制限 ─ **最も重大な差分**

### 規定（一次資料）

競技に関する連盟特別規則《学童部（女子共）》7 学童部の投球数制限について

1. 1試合かつ1日の投球数は **70球以内**。なお、4年生以下が投手として出場した場合の投球数制限は**学年で判断**する（**4年生以下は60球以内**）
2. 特別継続試合で投球できる球数は、もとの試合で投じた球数を引き継ぎ、残りの球数だけとする
3. 特別継続試合に勝利したチームの投手は、同日に行われる試合において1日の投球数制限を超えない範囲で登板できる
4. **1週間 210球以内（4年生以下は180球以内）** ← 2026年シーズンより導入

### アプリの状態

| 規定 | 状態 |
|---|---|
| 投手ごとの投球数を数える | **済**（FR-19） |
| 70球／60球の上限と対比して見せる | **未** |
| 4年生以下かどうかを判別する | **不可能**。アプリは背番号しか持たず、学年を持っていない |
| 1日の投球数（複数試合の合計） | **不可能**。1試合分しか保持しない |
| 1週間の投球数 | **不可能**。同上 |
| 特別継続試合の球数引き継ぎ | **不可能**。概念がない |

### 評価

**「投手の投球数を可視化する」が本アプリの副次的な目的（v0.3 §1.4）である以上、これは看過できない。**

現状は「その試合でその投手が何球投げたか」しか出せない。規定が求めているのは **1日** と **1週間** の合計であり、いずれも1試合のデータからは原理的に出せない。

- **1日**：ダブルヘッダーや連戦で成立する。学童では普通に起きる
- **1週間**：2026年シーズンから適用。**試合をまたいでデータを保持しなければ絶対に出せない**

v0.3 は Phase 2 に「サーバ同期と選手マスタ」を置いているが、**週間投球数はマスタと履歴が前提**であり、Phase 2 の優先度を上げる根拠になる。少なくとも「過去の試合を端末内に残す」ところまでは Phase 1 の延長で可能である（現在は「新しい試合」で前の試合が消える）。

**学年の扱いは判断が要る。** 4年生以下かどうかで上限が 70/60 と変わるため、学年を持たないと上限判定ができない。氏名を登録しない方針（FR-14）と違い、学年は個人を特定しないので保持しても方針に反しないと考えられる。

なお v0.3 §4.4 は「投球数制限の警告通知」をやらないと決めているが、これは**通知**の話であって、**上限値の表示**まで否定していない。現状は上限が画面のどこにも出ていない。

## 2. 再出場（リエントリー） ─ **記録できない可能性**

### アプリの状態

一度退いた選手の再出場を **拒否している**（`validateSub`）。FR-18 は「未」で、RuleConfig とあわせて Phase 2 としていた。

### 評価

**学童では再出場が認められている運用が一般的で、認められているなら現状のアプリでは正しい記録ができない。** 再出場した時点で入力が止まる。

記法規約側にも `LineupEntry.entryType` に「リエントリー」が定義されており、紙では記録できる前提になっている。**紙で記録できてアプリで記録できないのは、移行の障害として最も重い部類**である。

所属連盟の規約で可否と回数を確認し（OPEN-03）、認められているなら Phase 1 の残作業として扱うべきである。

## 3. タイブレーク ─ **構造上、記録できない**

### 規定

延長は継続打順・無死満塁から始める方式が広く使われている（大会規定による）。

### アプリの状態

**イニング開始時に必ず走者なしから始まる**（`endHalf` が `bases` を空にする）。走者を置いた状態でイニングを開始する手段がない。

### 評価

**タイブレークに入った試合は記録できない。** 回避策として、イニング頭に「打撃妨害」などで走者を無理やり置くことになるが、記録として誤りになる。

イベント列に「タイブレーク開始（走者を置く）」を追加する必要がある。記法規約にも該当する記号がないため、**記法側にも確認が要る**（紙ではどう書いているのか）。

## 4. 試合の終わり ─ 概念がない

### 規定

学童は6回制（または7回制）、時間制限あり、得点差コールドあり。いずれも大会規定で変わる。

### アプリの状態

**イニングが無制限に進む。** 「試合終了」を記録する手段がなく、規定回数・コールド・時間切れのいずれも扱えない。

### 評価

記録そのものは続けられるので実戦で止まりはしないが、以下に影響する。

- 印刷（FR-23）で「どこで試合が終わったか」が出せない
- 記法規約 §8 の **残塁 `ℓ`** と、3アウト時の欄外 `//` は、イニングの終了と対になる
- 集計5項目（記法規約 §11）を「試合終了後に記入する」ため、終了の区切りが要る

v0.3 §7.2 の RuleConfig に「規定イニング数、コールド条件、時間制限」が挙がっているのは設計として正しい。**未実装なだけ**である。

## 5. 特別継続試合

### 規定

- 投球数は元の試合で投じた球数を引き継ぎ、残りの球数のみ
- 試合時間についても残りの試合時間のみで行う

### アプリの状態

概念がない。中断・再開した試合を1つの試合として扱う手段がない。

### 評価

頻度は低い。ただし **JSON の書き出し／読み込みがあるため、再開自体は現物として可能**である。引き継ぎの明示（この試合は継続試合である、開始時点の球数はいくつか）が持てていないだけなので、対応は軽い。

## 6. 照合の結果、問題がなかったもの

| 項目 | 確認内容 |
|---|---|
| 指名打者（DH） | 全軟連主催大会で使用できるが、**少年・学童部は今後導入を検討**とされており現時点で未導入。アプリにも記法規約にも DH がないのは**整合している** |
| 申告敬遠 | 記法規約に `B'`（敬遠四球、申告含む）があり、アプリにも「敬遠四球」を実装済み |
| チーム編成 | 上限25名（令和4年度改定で20名→25名）。アプリは打順枠に人数無制限（FR-17）なので抵触しない |
| 打順9人 | アプリは9枠固定。学童の通常編成と一致 |
| 負傷治療時間 | 学童部では試合時間に算入しない。アプリは時間を扱っていないため影響なし |
| 使用球・用具 | J号（学童部）、D号（学童低学年）、金属スパイク不可など。記録の対象外 |

## 7. 対応の優先度

実戦投入（v0.3 §11）までにどこまで必要かで並べる。

| 優先 | 項目 | 理由 |
|---|---|---|
| **高** | 再出場（リエントリー） | 認められているなら、出た瞬間に記録が止まる |
| **高** | タイブレーク時の走者設定 | 延長に入った瞬間に記録が止まる |
| **中** | 投球数の上限表示（70/60球） | 数えていても上限が見えなければ、ベンチが判断できない |
| **中** | 試合終了（規定回数・コールド・時間切れ） | 印刷と集計の前提。記録は止まらない |
| **低** | 学年の保持 | 上限の自動判定に必要。手動で上限を設定すれば回避できる |
| **低** | 1日・1週間の投球数 | 試合をまたぐ保持が前提。Phase 2 の同期・マスタと同時 |
| **低** | 特別継続試合 | 頻度が低く、JSON の入出力で代替できる |

**上2つは「記録が止まる」種類の欠落**であり、他とは性質が違う。v0.3 §12.6「記録を止めない」に照らすと、保留（あとで決める）でも回避できない。
